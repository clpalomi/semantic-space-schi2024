# Input structure inferred from the scripts

These are minimum code requirements, not an assertion about the original data dictionary. Clinical data and preprocessing code were not included. No study records are provided.

```text
data/
  texts/
    <participant_session>_bild_1.txt
    <participant_session>_bild_2.txt
    <participant_session>_bild_4.txt
    <participant_session>_bild_6.txt
  metadata/
    ssd_mdd_hc_data.csv
    groups.xlsx                 # generated by stage 01, or supplied directly
    symptoms.xlsx
  templates/                    # headers only; never read as study inputs
```

## Transcripts

One nonempty UTF-8 German transcript per participant/session and picture. For example, `P001_session_bild_1.txt` joins to a metadata `name` of `P001_session`. The code removes the final seven characters (`_bild_1`) when matching subjects, so picture identifiers must remain single-digit. Pictures `1`, `2`, `4`, `6` correspond to the TAT prompts described in the SM (including 4BF as `4`).

Subfolders are searched recursively, but filenames must be unique across subfolders: dictionaries use filenames, not full paths. The sentence reader uses `.`, `!`, `?` and newlines, and appends a final period when necessary. These operations do not replace the unavailable original transcript preprocessing.

The semantic calculations assume sufficient sentences and non-stopword tokens. A one-sentence speech, empty filtered sequence or too few transitions can trigger undefined values or divisions by zero in the supplied code. Do not silently delete such records to obtain a result. Record eligibility and any exclusion decision separately. Convex hulls use the source's explicit sentence-count thresholds; see the reproducibility notes.

## Participant metadata

`ssd_mdd_hc_data.csv`: one row per participant/session.

| Column | Used for |
| --- | --- |
| `Proband` | Identifier matching the transcript prefix; becomes `name` |
| `Typ2` | Group string: `HC`, `MDD`, `SSD` in the main analyses |
| `Typ` | Subgroup; becomes `s_group` |
| `SKID_Diagnose_1` | Diagnosis field; becomes `type` |
| `Alter` | Age |
| `Geschlecht` | Sex coding used by the source: 1 → M, 2 → F |
| `Bildungsjahre` | Years of education |
| `IQ` | IQ |
| `AgeOfOnset` | Age at onset |

The first four columns suffice for stage 01 and feature extraction; demographic tables require the remaining columns. Preserve identifiers as strings and avoid ambiguous numeric-only identifiers or Excel conversion of leading zeros. No automatic group-label conversion is performed. Older additional scripts expect `Sz`/`MD` instead of `SSD`/`MDD`; they cannot be mixed blindly with the main stages.

`groups.xlsx` must contain `name`, `group`, `s_group`, `type`. Even when the latter two fields are not part of a result, several scripts drop them explicitly and expect them to exist. This file can be prepared directly instead of running stage 01. Both it and the demographic CSV should have unique identifiers.

## Symptoms

`symptoms.xlsx`: one row per `name`, with numeric symptom measurements. Do not include a second `group` column in this workbook: the main symptom script gets string group labels from the feature/volume results.

The required columns are listed in `data/templates/symptoms.csv`:

- `name`
- `SANS_Sum_ENIGMA`, `SANS_Affektverflachung_ENIGMA`, `SANS_AlogieParalogie_ENIGMA`, `SANS_AbulieApathie_ENIGMA`, `SANS_Anhedonie_ENIGMA`, `SANS_Aufmerksamkeit_ENIGMA`, `SANS_Sum_ohneAufmerksamkeit_ENIGMA`
- `SAPS_Halluzinationen_ENIGMA`, `SAPS_Wahn_ENIGMA`, `SAPS_BizarresVerhalten_ENIGMA`, `SAPS_PositiveFormaleDenkstoerung_ENIGMA`, `SAPS_Sum_ENIGMA`
- `HAMD_Sum17`, `HAMA_Sum`, `YMRS_Sum`, `GAFscore`

The supplied symptom analysis replaces `-99` and `-93` with missing values. The demographic description replaces `-99` only. These conventions are preserved. Symptom/feature merges are inner joins on `name`; subjects without a matching row are not represented. The script computes both per-picture correlations and correlations after averaging measures per subject. The partial analysis controls for dummy-coded string groups.

## Additional inputs

The Santander comparison expects `data/santander/new_merged_sentences.xlsx`. Its required original columns and recoding appear in `additional/31_centroids_santander.py`; it is not used by the main German workflow. Additional coreference analyses also require fields/intermediates not produced by the attachments. Consult `additional/README.md` before attempting them.

Generated `.pkl` files live under `results/`, not `data/metadata/`. Read only trusted pickle files. Header templates are provided as CSV for inspection; convert them to the required Excel workbook format and supply actual authorized measurements before running an analysis.
